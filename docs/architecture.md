# Architecture

Status: Phase A (Tauri shell) is implemented in `app/` and measured
(371.1 MB idle private, see `research/measurements.md`); Phase B (renderer
plugins) is next. See [roadmap.md](roadmap.md).

## Overview

```
+-------------------------------------------------------------+
|  Mirlo (Rust process)                                       |
|                                                             |
|  +-------------------+      +----------------------------+  |
|  |  Native shell     |      |  WebView2 (system runtime) |  |
|  |  - window/tray    | IPC  |  music.youtube.com         |  |
|  |  - hotkeys        |<---->|  + injected bridge script  |  |
|  |  - settings store |      |  + renderer plugin logic   |  |
|  |  - adblock filter |      +----------------------------+  |
|  |  - SMTC/media     |                 ^                    |
|  +-------------------+                 | session cookies    |
|          ^                             |                    |
|          | sidecars (v1+)              |                    |
|   notifications, scrobbler,       %LOCALAPPDATA%\Mirlo\     |
|   discord RPC, api-server         webview2-profile\        |
+-------------------------------------------------------------+
```

- **Shell**: Tauri 2 (Rust). Owns windows, tray, global hotkeys, settings,
  notifications, single-instance and (later) auto-update.
- **WebView2**: renders the official player. A persistent user-data folder
  keeps the user's Google session across restarts.
- **Bridge**: an initialization script runs in every page load and (a) forwards
  player state to the shell, (b) receives commands to control the player, and
  (c) loads renderer plugin logic. The channel mirrors the inherited `ytmd:*`
  contract of pear-desktop (see `research/ipc-contract.md`), re-expressed as
  Tauri commands/events.
- **Ad-block**: v0 blocks via injection (validated in the PoC). v1 moves
  blocking to the network layer (`WebResourceRequested` on the WebView2
  controller) for coverage and performance. Ships OFF by default (ADR-0003).

## Phase A implementation (`app/`)

- **Window** (created from Rust, not from config): `WebviewUrl::External` to
  `https://music.youtube.com/` with `data_directory` at
  `%LOCALAPPDATA%\Mirlo\webview2-profile` (WebView2 appends `EBWebView`, the
  same layout the Phase 0 PoC produced, so sessions carry over).
- **Bridge**: `src-tauri/src/bridge.js`, injected at document start with the
  boot config templated into `window.__MIRLO_BOOT__`. Command surface
  (renderer → shell): `get_config`, `set_config`, `get_path`,
  `report_player_state`, `reload_player`, `restart_app`. Shell → renderer:
  global hotkeys `eval` `window.__mirlo.player.{playPause,next,previous}`.
- **Remote IPC grant**: the player page is remote content, so Tauri requires
  an explicit capability (`capabilities/main.json`): `remote.urls` plus
  app-permission entries (`allow-<command>`) generated by `build.rs`'s
  `AppManifest::commands`. Without them, invokes fail with
  `Command … not allowed by ACL`.
- **Settings**: one JSON file (`config.json`) written atomically; defaults
  are persisted on first run. `adblock` ships `false` (ADR-0003) and is
  applied by the bridge only at document start.
- **Debugging**: `MIRLO_DEBUG_PORT=9222` enables the WebView2 CDP endpoint
  for local inspection (env-gated, off by default).
- The console stays attached in Phase A for development visibility; packaging
  (Phase D) will switch to `windows_subsystem = "windows"` plus a log file.

## Plugin model

**Implemented (Phase B, batch 1).** The injected bridge exposes a plugin host
(`window.__MIRLO_PLUGINS__`) with this shape:

- `register(id, def)` — each plugin file (one per upstream plugin) declares
  `defaults` (option defaults, including `enabled`), optional `styles` (CSS,
  injected as adopted stylesheets while active) and lifecycle methods
  `start(ctx)`, `onPlayerApiReady(api, ctx)`, `onConfigChange(cfg)`, `stop()`.
- **Config** — per-plugin options live in `config.json` under `plugins`
  (`{ "<id>": { "enabled": bool, ...options } }`; schema v2). The shell stores
  only user changes; defaults live in the plugin file. `ctx.setConfig()`
  persists through the `set_plugin_config` command.
- **Compatibility** — the YouTube player element's native `videodatachange`
  event is re-emitted on `document` (and `ytmd:src-changed` on the video at
  `dataloaded`), mirroring pear-desktop's `song-info-front`, so ported plugin
  code needs minimal diffs.
- The boot config (`window.__MIRLO_BOOT__`) is templated per window creation;
  the host refreshes through `get_config` at init, so config edits apply on
  page reload without restarting the app.

Two classes of plugins, matching what Phase 0 found in pear-desktop v3.11.0
(`research/plugin-inventory.md`):

1. **Renderer plugins (~29 of 41)** — DOM/CSS/Web Audio logic with no Electron
   dependency. Ported almost 1:1 into the injected bridge, behind a simple
   enable/disable + config store owned by the shell.
2. **Native-bridge plugins (~10)** — small, well-delimited native
   integrations. Each maps to a Rust module or crate:

   | Plugin (upstream) | Mirlo approach |
   |---|---|
   | notifications | Tauri notification plugin |
   | precise-volume / shortcuts | Tauri global-shortcut |
   | taskbar-mediacontrol | SMTC via `windows` crate (media keys + overlay) |
   | scrobbler | Webview window for Last.fm auth + `reqwest` |
   | discord | Rust rich-presence crate |
   | lumiastream / tuna-obs | WebSocket clients (`tokio-tungstenite`) |
   | api-server | HTTP server (`axum`) on localhost |
   | in-app-menu (heavy) | Start with native Tauri menu; custom overlay later |

   Excluded by policy: `downloader` (ADR-0003) and `touchbar` (macOS-only).

## Security posture

- Remote page content gets **no privileged IPC**: the bridge is a strict,
  reviewed command surface (settings get/set, player control, plugin config).
  No arbitrary command execution, no filesystem access from page context.
- The WebView profile folder is app-private under `%LOCALAPPDATA%\Mirlo`.
- No analytics, no telemetry, no network calls except the user's own service
  usage and explicitly enabled integrations.

## Performance targets

- Idle private memory (Task Manager metric): **< 450 MB** target for Phase A —
  measured **371.1 MB** (Phase 0: bare WebView2 shell at 399 MB; Electron
  build at ~1.2 GB).
- Idle CPU: single-digit percent; no polling loops (event-driven only).
- Cold start to interactive player: target < 3 s on typical hardware.

## Distribution (Phase D)

- Windows first: NSIS/MSI installer via Tauri bundler, per-user install.
- No bundled browser runtime (WebView2 Evergreen dependency documented and
  bootstrapped by the installer if missing).
- Auto-update via Tauri updater on signed GitHub releases.
